# 行为型设计模式实践

## 行为型模式概述

行为型模式关注对象间通信与职责分配。本文覆盖策略、模板方法、观察者、责任链、状态五种高频模式。

## 策略模式

将算法封装在独立策略类中，运行时可互相替换。

| 对比 | if-else | 策略模式 |
|------|---------|----------|
| 可扩展性 | 改原有代码 | 加新策略类 |
| 可读性 | 条件多难维护 | 职责清晰 |
| 开闭原则 | 不符合 | 符合 |

Spring 实践：策略接口 + `@Component` 具体策略 + 工厂注入 `Map<String, DeliveryStrategy>`（Spring 自动按 Bean 名注入 Map）。

常与模板方法组合：`AbstractDeliveryStrategy` 定义 validate → doDeliver → notify 骨架，子类只实现 `doDeliver`。

## 模板方法模式

父类定义算法骨架（`final` 模板方法），差异步骤留给子类（抽象方法）或钩子方法。

典型场景：数据导出（校验→查数→转换→写文件→通知），CSV/Excel 只覆写 transform/write。

## 观察者模式

一对多依赖：被观察者状态变化时通知所有观察者。

工程映射：Spring ApplicationEvent / `@EventListener`；商品价格监控可挂降价推送、日志、库存预警多个观察者。

## 责任链模式

将请求发送者与接收者解耦，多个处理器组成链依次处理。

应用：FilterChain、审批流、异常处理链、权限校验链。

电商退款示例：校验 → 客服(≤100) → 主管(≤1000) → 经理；金额决定在哪一环终结。

工程映射：Ragent 后处理责任链（order 1-20）、MyBatis Interceptor、12306 责任链校验。

## 状态模式

对象内部状态改变时改变行为；状态相关行为封装在独立状态类中。

应用：订单状态机、工单流转（草稿→待处理→处理中→已解决→关闭）、播放器。

每个状态类实现全部动作接口，非法转移在状态内拒绝；上下文委托当前状态处理。

## 行为型选型指南

| 模式 | 适用场景 | 核心价值 |
|------|----------|----------|
| 策略 | 多种算法动态切换 | 算法封装，开闭 |
| 模板方法 | 流程固定、步骤可变 | 代码复用 |
| 观察者 | 一对多状态通知 | 解耦，事件驱动 |
| 责任链 | 多处理器依次处理 | 灵活组合 |
| 状态 | 行为由状态决定 | 转换清晰 |
