# MVC 架构模式与设计模式组合实战

## MVC 各层职责

| 层 | 职责 | 工程形态 |
|----|------|----------|
| Model | 核心数据与业务规则 | 领域实体、领域服务 |
| View | 数据呈现与交互，无业务逻辑 | VO/DTO、模板、前端页面 |
| Controller | 接收输入、调模型、选视图 | `@RestController` |

核心价值：关注点分离、可维护、可并行开发、可独立测试。

## Spring MVC 落地要点

- Controller 只做参数校验与编排，业务进 Service/Domain
- View 侧用 VO 脱敏（如邮箱 mask），禁止把实体直接抛前端
- 激活等状态变更是 Model 的业务方法，不是 Controller 里的 if

## 设计模式组合实战（支付渠道）

场景：多支付渠道（微信/支付宝/银联），流程骨架相同、渠道实现不同。

组合方式：
1. **策略**：`PaymentStrategy` 按渠道切换
2. **工厂**：按 `payChannel` 取策略 Bean
3. **模板方法**：统一校验 → 调渠道 → 落单 → 回调处理骨架

这与行为型篇的配送策略工厂同构——生产中「策略 + 工厂 + 模板」是最高频组合。
